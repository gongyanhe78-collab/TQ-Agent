# 2026-08-27 个例分析四槽位与图片引用优化

## 问题

逐例分析原来包含过程画像、关键致灾链、复合风险、预报服务复盘和可迁移启示五个槽位。正文模型每例最多只能读取六个精选 chunk，而不少个例没有完整的预报、预警和服务材料。将预报服务设为必选槽位并强制为其保留 chunk，会挤占过程机理和影响证据名额，同时在报告中产生较多“材料未给出预报、预警或服务记录”等模板化边界句。

图片方面，需要保证模型在分析六个 chunk 时能同时读取当前个例全部关联图片的图注，并且只有正文实际引用的图片才进入网页和 PDF。此前已存在图注传递和按引用筛图链路，本次将该行为明确写入四槽位协议，并增加端到端测试防止回退。

## 本次处理

### 1. 个例分析改为四个槽位

逐例模型只返回以下字段：

1. `process_profile`：过程画像，回答何时、何地、主导灾种、强度和演变；
2. `hazard_chain`：关键致灾链，只使用环流、温湿结构、地形、雷达和明确演变证据；
3. `compound_risk`：复合风险，只使用实况和实际影响材料，不按灾种标签臆测；
4. `transferable_insight`：可迁移启示，只能从前三部分已经证实的信号、区域、演变和阈值推导。

删除 `forecast_service_review` 必填槽位，正文不再生成“无法评价提前量、落区偏差和服务效果”的固定段落。后端仍将四部分组合为三段：过程画像、致灾链与复合风险、可迁移启示。

### 2. 六个 chunk 重新分配

- 强度指标继续由全量关联 chunk 的独立事实库提供，不占六个正文 chunk 的指标发现任务；
- 六个精选 chunk 的必选证据角色由“过程、机理、服务、影响”改为“过程、机理、影响”；
- rerank 查询优先寻找过程实况、环流与温湿结构、地形或雷达诊断、实际影响和复合风险；
- 不再强制用一个名额选择预报服务片段，从而提高关键致灾链和复合风险的材料覆盖率。

当致灾机理和复合风险都缺少证据时，后端只保留一次合并边界，不连续罗列多个“材料未给出”。可迁移启示缺少依据时同样不生成泛化的“加强监测”建议。

### 3. 图注与六个 chunk 同次输入模型

- 准备当前个例时，按 `evidence_image_ids` 和关联 `source_chunk_ids` 读取全部可解析图片元数据；
- 页面快照类图片会被过滤，同图注重复图片会去重；
- 模型上下文同时包含个例元数据、已核验强度事实、最多六个精选正文 chunk，以及全部候选图片的图片 ID 和完整图注；
- 此阶段只传图注元数据，不提前读取或下载图片文件；
- 模型只有在正文中使用完整图号或图题并说明图片支撑的具体判断时，才能把对应图片 ID 写入 `cited_image_ids`；
- 后端再次交叉校验正文图号、候选图注和 `cited_image_ids`。只有校验通过的图片才解析文件路径并进入网页和 PDF，其他关联图片不展示。

继续保留 2026-08-26 增加的开放式引用清理：`图N...`、`可参考图N...` 和 `图1、图2、...` 不会作为有效图片引用进入报告。

### 4. 缓存隔离

逐例正文缓存版本升级为 `case-analysis-v23-four-slots-image-citations`。旧五槽位正文和旧图片引用结果不会继续命中新协议。

## 验证

- 回归测试确认四槽位提示词不再包含 `forecast_service_review`；
- 回归测试确认六 chunk 角色覆盖包含过程、环流机理和实际影响，不再强制选择预报服务；
- 端到端测试同时传入两张关联图片图注，确认两张图注都进入模型上下文，但模型只引用一张时最终仅展示该图片；
- 保留正常图号、子图、并列图号、错误图号和开放式省略引用的既有测试；
- Python 编译、完整模块单元测试、本地数据源测试和差异格式检查结果以本次执行日志为准。
