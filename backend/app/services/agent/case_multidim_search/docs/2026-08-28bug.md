# 2026-08-28 统一聊天页面优化记录

## 背景

项目原有多维个例检索和相似个例匹配分别提供独立自然语言聊天页面。本次新增统一入口，使两种能力可以在同一聊天记录中切换。

## 实现

- 新增 `/api/case-unified/natural-chat` 页面路由。
- 输入框右侧增加“多维检索/相似个例匹配”模式选择；切换模式只影响下一次发送，不清空当前消息线程。
- 多维模式继续调用原有 `/api/case-multidim/natural/parse`、`/natural/search` 和 `/export-pdf`，确认条件后展示原有 PDF 预览和下载结果。
- 相似模式继续调用原有 `/api/smart-case-match/conversation/stream`，按原返回协议展示匹配个例、匹配理由、参考经验和综合研判。
- 多维检索会话编号保存在统一页面的本地会话状态中；页面可见的用户和助手消息统一追加到同一线程。两个 Agent 的业务逻辑、数据来源和接口协议均未修改。

## 验证

已进行 Python 编译检查和路由文件静态检查；启动后可访问 `http://127.0.0.1:8000/api/case-unified/natural-chat`。

## 2026-08-28 本次优化追加

- **重点个例强度汇总**：按主导灾种分别生成表格，固定前三列为“个例、主导灾种、并发灾害”，后三列从该灾种候选指标和已抽取的真实指标中动态选择。选择时统计每个指标的有效值个例数，优先全覆盖字段，其次要求覆盖率达到 `ceil(个例数×70%)`；候选不足时仅补入业务预设字段，缺失值显示“—”，不跨个例复制、不推断填值，并在日志记录覆盖数和填充率。
- **相似个例展示恢复**：统一聊天页恢复匹配理由、参考经验、关键差异、过程前历史预警，以及参考经验关联的文字 chunk 和图片证据按钮。点击文字证据读取 `/assets/chunks/{chunk_id}`，图片使用响应中的安全 URL 和图注展示。
- **处理阶段状态**：统一页状态改为处理中/完成/错误三态，处理中持续显示旋转加载图标，并在筛选个例、生成 PDF 等阶段更新阶段文字。
- **PDF 预览**：多维检索报告“查看”改为当前页面右侧内嵌 iframe 展开，保留独立下载按钮，不再新开页面。

验证：`python -m compileall -q backend` 通过；当前环境未安装 pytest，相关测试未能执行。

## 2026-08-28 统一页面回归核查与修复

### 现象

- 相似个例已经返回结果，但状态文字仍显示旋转加载图标。
- 多维页面查询“2025年2月至4月暴雨、短时强降水”显示 0 个命中个例。

### 原因与处理

- 相似个例接口的最终状态除了 `completed` 还可能是 `degraded`。统一页面原先只把 `completed` 当作终态，因此降级完成后仍处于处理中。现将 `completed`、`degraded` 均按业务完成处理，并在 SSE 已有结果但连接未发送终态时增加兜底完成状态，停止旋转图标；错误事件仍保持错误态。
- 多维统一页确认检索时改为优先使用解析提案返回的 `conversation_id`，与原多维页面的提案确认流程一致，避免跨会话提交导致上下文不匹配。
- 复核本地共享知识库后，日期条件 `[2025] + [2,3,4]` 可命中 8 个个例；但这 8 个标准化个例的灾种标签均为大风、雨雪、寒潮、降雪等，没有“暴雨”或“短时强降水”。因此 0 命中是结构化灾种硬过滤的真实结果，不是统一页面数量显示错误，也没有通过放宽过滤或伪造命中改变业务逻辑。
- 两个 Agent 仍分别调用既有接口，知识库仍由 `backend/app/services/agent/data` 统一提供；本次只修正统一页面展示层和会话参数兼容性。
