# 个例多维检索报告参考版式设计

## 目标

将个例多维检索智能体生成的 PDF 改为与 `resource/FST2025-6.pdf` 一致的简洁技术报告体例。报告以连续文字分析为主体，统计图和数据库原图仅作为分析证据，不再使用营销化封面、指标卡片、彩色色块或装饰性页眉。

## 参考版式参数

- 页面：A4 纵向，约 `595.3 x 841.9 pt`。
- 左右页边距：约 `85 pt`，折合约 `30 mm`。
- 正文：`12 pt`，基线间距约 `23.4 pt`，首行缩进约 `24 pt`。
- 一级章节标题：`15 pt`。
- 二级章节标题：约 `14 pt`。
- 图注：`9 pt`，图片下方居中显示。
- 颜色：正文和标题使用黑色，统计图与数据库原图可保留必要颜色。
- 页脚：仅保留居中页码，不显示章节名称、横线或其他装饰。
- 署名：不显示固定机构署名，以便智能体迁移到主项目。

## 报告结构

### 首页与综合概况

首页不单独制作封面。页面顶部居中显示报告标题和生成日期，随后直接进入“综合概况”。综合概况使用两到四个自然段回答以下问题：

1. 当前查询命中了哪些范围的个例。
2. 最重要的时间、灾种和空间特征是什么。
3. 强度指标与原始证据支持哪些判断。
4. 当前数据存在什么限制。

### 主要分析

主要分析按参考报告的编号章节组织，依次包含时间分布、灾种结构、空间特征、中心点强度和证据完整度。每个章节必须先给出分析段落，再在需要时插入对应统计图。原有重点发现卡片取消，重点结论改写为完整句子并融入正文。

统计图保持克制：

- 每张图只服务一个明确分析结论。
- 图表紧跟对应段落，不单独设置“图表展示页”。
- 图题位于图片下方，采用连续编号。
- 不使用大面积背景色、圆角容器或装饰边框。

### 代表个例

代表个例按“一、二、三”或相应章节编号连续编排，不再强制每个个例独占一页。每个个例包含：

1. 过程特征与影响范围。
2. 可追溯的强度指标及其含义。
3. 综合研判和业务关注重点。
4. 与文字分析对应的数据库原图及图注。

正文不显示融合得分、向量召回等内部技术字段。数据库中的残缺摘要、目录文本和重复段落不得直接进入报告；个例概况继续由结构化日期、灾种、区域和证据数量归纳生成。

### 结论与建议

结尾使用连续文字和编号条目汇总综合结论、业务建议及数据局限。结论必须对应前文事实，建议必须由灾种、空间、强度和证据分析推导，不复制数据库中的目录式原文。

## 数据与图片处理

- 保留现有旧路径重定位逻辑，确保数据库图片指向当前项目中的真实文件。
- 图片插入前必须验证存在且可解码。
- 图片按页面可用宽度等比例缩放，不拉伸、不裁掉关键区域。
- 同一图组可并排展示，但图注必须清晰且不超过页面宽度。
- 无图片时仅以普通正文说明证据缺失，不显示彩色占位框。

## 代码范围

主要修改范围限定为：

- `backend/app/services/agent/case_multidim_search/pdf_report.py`
- 必要时调整 `backend/app/services/agent/case_multidim_search/chart_tool.py`
- `tests/case_multidim_search` 中的报告版式和质量测试

不修改检索、融合、强度提取、图片路径重定位和接口协议的功能行为。

## 测试与验收

### 自动化测试

- 所有页面尺寸统一为 A4。
- PDF 每页均非空且不存在内容越界。
- 报告包含综合概况、主要分析、代表个例、结论建议和数据局限。
- 报告不再出现指标卡片、彩色页眉和独立图表页的版式结构。
- 数据库原图真实嵌入 PDF，关联图片路径全部存在。
- 个例概况不复制残缺数据库摘要。
- 每个生产代码和测试方法均保留中文注释或中文 docstring。

### 真实数据验收

- 使用当前真实标准个例库生成 `data/case_multidim_reports/postman-smoke-report.pdf`。
- 检查正文、标题、图注的字号层级与参考 PDF 一致。
- 检查正文行距、页边距、首行缩进和图文顺序。
- 检查统计图和数据库原图与对应分析内容一致。
- 逐页渲染检查页面尺寸、空白页、文字遮挡、图片变形和图注溢出。

## 非目标

- 不追求复刻参考 PDF 的原始 Word 模板或字体文件内部编码。
- 不增加新检索条件、新接口或新数据库字段。
- 不为报告增加交互、动画、品牌装饰或营销化视觉元素。
